# MQL5 Expert Advisor Development Guide

---

## Phase 1: Project Setup (Vibe Coding Template)

Before writing any code, establish the project frame using this 4-part template:

**Part 1 — Role & Goal**
Define Claude as an MQL5 expert with modular design focus. State the EA name, target instrument, and primary objective (full automation vs. alert-based).

**Part 2 — Constraints & Environment**
- Technologies: MT5 / MQL5
- Clean Code with minimal but meaningful comments
- No unnecessary features (Occam's Razor)
- Specify error handling points (e.g., indicator handle failure, order rejection, connection loss)

**Part 3 — Process Flow**
1. Summarize system architecture and logic flow for review before coding
2. Build in modules — start from the most critical component
3. Self-review each module for logical flaws and performance issues before delivery

**Part 4 — First Action**
Summarize project understanding and propose file structure or development sequence for confirmation.

## Phase 2: Pre-Coding Checklist

Verify these before implementation begins:

- [ ] Symbol naming convention confirmed (e.g., `US100Cash#`, `XAUUSD`, `AUDCAD#`)
- [ ] Broker account type confirmed: Netting or Hedging
- [ ] Target timeframe(s) defined (M1 / M5 / H1 / H4 / Daily)
- [ ] Higher timeframe trend filter defined (e.g., Daily EMA50/EMA200)
- [ ] Entry condition logic written in plain language before code
- [ ] SL/TP method defined: fixed points, ATR-based, or swing-based
- [ ] Lot sizing method defined: fixed or equity-based dynamic
- [ ] Kill switch / max drawdown threshold defined
- [ ] Notification method: MT5 push, Telegram, or popup alert
- [ ] Magic Number assigned

**Symbol handling rule (Strategy Tester critical):**
- Use `_Symbol` for all indicator creation and OHLC data calls
- Use `TradeSymbol` (input variable) only for order execution and `SymbolInfoDouble`
- Mixing these breaks Strategy Tester compatibility

## Phase 3: Strict Coding Rules (ห้ามละเมิด)

- MQL5 only — ห้ามใช้ฟังก์ชัน MQL4 (`OrderSend`, `OrdersTotal`, `OrderSelect`)
- Position management — ใช้คลาส `CTrade` จาก `#include <Trade\Trade.mqh>` เสมอ
- Memory management — Dynamic Array ต้องเรียก `ArrayFree()` เสมอ

### Required File Structure

```mql5
// 1. Property & Inputs
// 2. Include Libraries
#include <Trade\Trade.mqh>

// 3. Global Variables & Instances
CTrade trade;

// 4. OnInit()   — Initialization & Indicator Handles
// 5. OnDeinit() — Cleanup
// 6. OnTick()   — Core Logic
```

## Phase 4: Code Patterns

### Pattern A — Indicator Data (Handle + CopyBuffer)

```mql5
int maHandle;

int OnInit() {
    maHandle = iMA(_Symbol, _Period, 14, 0, MODE_SMA, PRICE_CLOSE);
    if (maHandle == INVALID_HANDLE) return INIT_FAILED;
    return INIT_SUCCEEDED;
}

void OnTick() {
    double maValues[];
    ArraySetAsSeries(maValues, true);
    if (CopyBuffer(maHandle, 0, 0, 3, maValues) < 0) {
        Print("Error copying MA data");
        return;
    }
    // maValues[0] = current candle
}
```

- สร้าง handle ใน `OnInit()` ครั้งเดียว
- `ArraySetAsSeries(arr, true)` → index 0 = candle ล่าสุด
- ตรวจสอบ return value ของ `CopyBuffer` ก่อนใช้ค่าเสมอ

### Pattern B — Order Execution

```mql5
// Buy
double ask = SymbolInfoDouble(_Symbol, SYMBOL_ASK);
trade.Buy(lotSize, _Symbol, ask, sl, tp, "Buy Comment");

// Sell
double bid = SymbolInfoDouble(_Symbol, SYMBOL_BID);
trade.Sell(lotSize, _Symbol, bid, sl, tp, "Sell Comment");
```

ห้ามคำนวณ Ask/Bid ด้วยตนเอง — ใช้ `SymbolInfoDouble` เสมอ

### Pattern C — Position Checking

```mql5
bool IsPositionOpen() {
    for (int i = PositionsTotal() - 1; i >= 0; i--) {
        if (PositionGetSymbol(i) == _Symbol)
            return true;
    }
    return false;
}
```

## Phase 5: Backtest Result Verification

After receiving a Strategy Tester report, verify all thresholds before proceeding:

| Metric | Minimum Threshold |
|---|---|
| Equity Drawdown Maximal (%) | ≤ 18% |
| Equity Drawdown Relative (%) | ≤ 18% |
| Balance Drawdown Maximal (%) | ≤ 18% |
| Profit Factor | ≥ 1.50 |
| Recovery Factor | ≥ 1.50 |
| Win Rate (%) | ≥ 60% |
| Sharpe Ratio | ≥ 1.50 |

**Evaluation rule:** If any metric fails its threshold, flag it explicitly before recommending further optimization or live deployment. Do not proceed to next phase until all thresholds pass.

**Common failure patterns to check:**
- Win rate 27–29% → below breakeven; consider pivot to alert-based system
- Low trade count on H1 (e.g., <10 trades / 5 years) → parameters need timeframe-specific tuning
- High drawdown in 2020/2022 periods → ATR volatility filter likely missing or misconfigured
- `RequireBothEMA=true` blocking too many trades → review trend filter sensitivity
